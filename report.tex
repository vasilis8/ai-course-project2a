\section{Εισαγωγή}
% ============================================================

Στην παρούσα εργασία υλοποιούμε τρεις αλγορίθμους τοπικής αναζήτησης για δύο κλασικά
προβλήματα ελέγχου: \textit{\textlatin{CartPole}} και \textit{\textlatin{MountainCar}}.
Σε αντίθεση με το τυπικό πλαίσιο, τα περιβάλλοντα εδώ είναι \textbf{μη-στατικά}
(\textlatin{non-stationary}): οι φυσικές τους παράμετροι αλλάζουν κατά τη διάρκεια της
εκτέλεσης, οπότε δεν μπορούμε να βασιστούμε σε ένα σταθερό μοντέλο μετάβασης.

Για την προσομοίωση χρησιμοποιούμε τη βιβλιοθήκη \texttt{\textlatin{ns-gym}}, η οποία
επεκτείνει το \texttt{\textlatin{gymnasium}} ώστε να υποστηρίζει δυναμικές αλλαγές
παραμέτρων. Συγκεκριμένα:

\begin{itemize}
    \item \textbf{\textlatin{CartPole}}: η μάζα της ράβδου (\texttt{\textlatin{masspole}})
    αυξάνεται σταδιακά μέσω \texttt{\textlatin{IncrementUpdate}}, ενώ η βαρύτητα
    (\texttt{\textlatin{gravity}}) μεταβάλλεται τυχαία μέσω \texttt{\textlatin{RandomWalk}}.
    \item \textbf{\textlatin{MountainCar}}: τόσο η βαρύτητα (\texttt{\textlatin{gravity}}) όσο
    και η δύναμη του κινητήρα (\texttt{\textlatin{force}}) αυξάνονται σταδιακά μέσω δύο
    ανεξάρτητων \texttt{\textlatin{IncrementUpdate}}.
\end{itemize}

Οι αλγόριθμοι \textlatin{Hill Climbing}, \textlatin{Random Restart Hill Climbing} και
\textlatin{Simulated Annealing} εφαρμόζονται \textlatin{online}: σε κάθε βήμα ο πράκτορας
αξιολογεί τις διαθέσιμες κινήσεις μέσω προσομοίωσης και επιλέγει χωρίς να γνωρίζει τη
δυναμική του συστήματος. Οι αλγόριθμοι βασίζονται στο κεφάλαιο~4 του
\textlatin{Russell \& Norvig}.

\section{Αλγόριθμοι Τοπικής Αναζήτησης}
% ============================================================

\subsection{\textlatin{Hill Climbing}}

Ο \textlatin{Hill Climbing} (\textlatin{HC}) επιλέγει σε κάθε βήμα την κίνηση με τη
μεγαλύτερη άμεση αξία, χωρίς να κρατά ιστορικό και χωρίς να κοιτά πέρα από τον επόμενο
χρόνο. Είναι ο απλούστερος από τους τρεις αλγορίθμους και λειτουργεί αμιγώς
\textlatin{greedy}.

Σε κάθε κλήση της \texttt{\textlatin{act()}}, ο πράκτορας λαμβάνει αντίγραφο του
περιβάλλοντος και δοκιμάζει κάθε δυνατή κίνηση σε αυτό. Αν όλες οδηγούν σε τερματισμό,
επιστρέφεται $-1$ και γίνεται τυχαία επιλογή.

\begin{lstlisting}[language={}, caption={\textlatin{Hill Climbing -- act(env)}}]
best_action = -1,  best_value = -INF
for a in {0, ..., |A|-1}:
    sim = deepcopy(env)
    _, r, term, trunc = sim.step(a)
    if term: continue
    v = calculate_value(t=sim.env.t, r, term, trunc)
    if v > best_value:
        best_value = v;  best_action = a
return best_action
\end{lstlisting}

Το κύριο αδύνατο σημείο του \textlatin{HC} είναι η εγκλώβιση σε τοπικά βέλτιστα: αν η
καλύτερη άμεση κίνηση παραμένει η ίδια, ο αλγόριθμος δεν έχει κανέναν μηχανισμό να
βγει από αυτήν, ακόμα και όταν το περιβάλλον έχει αλλάξει σημαντικά.

\subsection{\textlatin{Random Restart Hill Climbing}}

Ο \textlatin{Random Restart Hill Climbing} (\textlatin{RRHC}) αντιμετωπίζει το πρόβλημα
των τοπικών βέλτιστων εκτελώντας $N$ τυχαίες δοκιμές και κρατώντας το καλύτερο
αποτέλεσμα. Κάθε δοκιμή επιλέγει τυχαία μια πρώτη κίνηση $a_0$, την αξιολογεί
σε βάθος $H$ βημάτων και αθροίζει τις αξίες. Χρησιμοποιούμε $N=20$ και $H=5$.

\begin{lstlisting}[language={}, caption={\textlatin{Random Restart HC -- act(env)}}]
action_values[a] = -INF  for each a
for i = 1 to N:
    sim = deepcopy(env);  a0 = random(A)
    _, r, term, trunc = sim.step(a0)
    if term: continue
    total = calculate_value(sim.env.t, r, term, trunc)
    for j = 2 to H:
        if term or trunc: break
        a = random(A)
        _, r, term, trunc = sim.step(a)
        total += calculate_value(sim.env.t, r, term, trunc)
    if total > action_values[a0]:
        action_values[a0] = total
return argmax_a action_values[a]
\end{lstlisting}

Το πλεονέκτημα έναντι του \textlatin{HC} είναι ότι ο ορίζοντας $H$ επιτρέπει στον
πράκτορα να αξιολογήσει τις συνέπειες μιας κίνησης πέρα από το άμεσο επόμενο βήμα,
κάτι που γίνεται πιο σημαντικό καθώς οι παράμετροι του περιβάλλοντος αποκλίνουν.

\subsection{\textlatin{Simulated Annealing}}

Ο \textlatin{Simulated Annealing} (\textlatin{SA}) εισάγει πιθανοτική αποδοχή χειρότερων
κινήσεων, εμπνευσμένος από τη διαδικασία ανόπτησης μετάλλων. Με υψηλή
θερμοκρασία $T$ ο πράκτορας εξερευνά ελεύθερα, ενώ καθώς το $T$ μειώνεται συγκλίνει
σε \textlatin{greedy} συμπεριφορά.

Αφού αξιολογηθούν όλες οι κινήσεις, η καλύτερη $a^*$ γίνεται αποδεκτή άμεσα. Μια
τυχαία εναλλακτική $a_c$ γίνεται αποδεκτή με πιθανότητα $e^{\Delta/T}$, όπου
$\Delta = V(a_c) - V(a^*) < 0$.

\begin{lstlisting}[language={}, caption={\textlatin{Simulated Annealing -- act(env)}}]
T = get_temperature();  step_count += 1
action_values = {}
for a in {0, ..., |A|-1}:
    sim = deepcopy(env)
    _, r, term, trunc = sim.step(a)
    if not term:
        action_values[a] = calculate_value(sim.env.t, r, term, trunc)
if action_values is empty: return -1
a_best = argmax action_values
a_c    = random(action_values.keys())
delta  = action_values[a_c] - action_values[a_best]
if delta >= 0 or U(0,1) < exp(delta / T):
    return a_c
return a_best
\end{lstlisting}

\paragraph{Στρατηγικές ψύξης.}
Δοκιμάσαμε τρεις στρατηγικές μείωσης της θερμοκρασίας, όπου $n$ είναι ο
αριθμός βημάτων που έχουν εκτελεστεί συνολικά (δεν επαναφέρεται μεταξύ επεισοδίων):

\begin{itemize}
    \item \textbf{Εκθετική (επιλεγμένη)}: $T_n = T_0 \cdot \alpha^n$, με $T_0 = 2.0$, $\alpha = 0.95$.
    \item \textbf{Γραμμική}: $T_n = \max(T_0 - \alpha \cdot n,\; \varepsilon)$, $\varepsilon = 10^{-3}$.
    \item \textbf{Λογαριθμική}: $T_n = T_0 / \ln(n + 2)$.
\end{itemize}

Επιλέξαμε την εκθετική γιατί μειώνει την θερμοκρασία ομαλά και δίνει στον αλγόριθμο
αρκετό χρόνο εξερεύνησης πριν συγκλίνει. Η λογαριθμική είναι θεωρητικά βέλτιστη αλλά
πολύ αργή για πεπερασμένα βήματα, ενώ η γραμμική φτάνει στο κατώτατο όριο $\varepsilon$
γρήγορα και γίνεται ουσιαστικά ντετερμινιστική.

\section{Πειραματική Διαδικασία}
% ============================================================

Για κάθε περιβάλλον και αλγόριθμο εκτελούμε δύο πειράματα:

\paragraph{Πείραμα 1.}
Για κάθε τιμή \texttt{\textlatin{max\_timesteps}} $\in \{10, 100, 500, 1000\}$ τρέχουμε
100 επεισόδια και υπολογίζουμε τη μέση αθροιστική ανταμοιβή. Το γράφημα έχει άξονα $x$
το \texttt{\textlatin{max\_timesteps}} και άξονα $y$ τη μέση ανταμοιβή.

\paragraph{Πείραμα 2.}
Για \texttt{\textlatin{max\_timesteps}} $= 100$ τρέχουμε 1000 επεισόδια και
απεικονίζουμε την ανταμοιβή ανά επεισόδιο, ώστε να φαίνεται πώς επηρεάζει η
μεταβολή του περιβάλλοντος την πορεία των αλγορίθμων στον χρόνο.

Η αρχικοποίηση γίνεται με \texttt{\textlatin{seed = 42 + ep}} για κάθε επεισόδιο
\texttt{\textlatin{ep}} ώστε τα αποτελέσματα να είναι αναπαραγώγιμα. Τα πειράματα
τρέχουν χωρίς οπτικοποίηση (\texttt{\textlatin{render\_mode=None}}) από το αρχείο
\texttt{\textlatin{test/run\_experiments.py}}.

\subsection{\textlatin{CartPole}}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\textwidth]{images/cartpole_mean_rewards.png}
    \caption{\textlatin{CartPole} -- Μέση αθροιστική ανταμοιβή ανά \texttt{\textlatin{max\_timesteps}}
    (100 επεισόδια). Η ανταμοιβή σταθεροποιείται γύρω στα 21--22 βήματα από τα
    \texttt{\textlatin{max\_timesteps}}=100 και πάνω, αντανακλώντας τον περιορισμό που
    επιβάλλει η μη-στασιμότητα. Ο \textlatin{RRHC} αποδίδει καλύτερα στα μεγαλύτερα
    \texttt{\textlatin{max\_timesteps}}.}
    \label{fig:cartpole_mean}
\end{figure}

Το Σχήμα~\ref{fig:cartpole_mean} αποκαλύπτει ένα ενδιαφέρον μοτίβο: για
\texttt{\textlatin{max\_timesteps}}$=10$ και οι τρεις αλγόριθμοι επιτυγχάνουν τέλεια
βαθμολογία 10 (επιβίωση σε όλα τα βήματα), αλλά από \texttt{\textlatin{max\_timesteps}}$=100$
και άνω η μέση ανταμοιβή παγώνει στα 21--24 βήματα ανεξαρτήτως του διαθέσιμου
budget. Αυτό δεν είναι τυχαίο: η σταδιακή αύξηση της \texttt{\textlatin{masspole}}
και η τυχαία μεταβολή της \texttt{\textlatin{gravity}} κάνουν το περιβάλλον αρκετά
δύσκολο ώστε ο πράκτορας να αποτυγχάνει γύρω στο βήμα 21, ανεξάρτητα από το πόσα
βήματα επιτρέπονται.

Μεταξύ των αλγορίθμων, ο \textlatin{RRHC} ξεχωρίζει στα μεγαλύτερα
\texttt{\textlatin{max\_timesteps}}: φτάνει ~23.3 στα 1000 βήματα, ενώ ο \textlatin{HC}
παρουσιάζει ελαφρά πτώση στα 500 ($\approx 20.5$) πριν ανακάμψει. Ο \textlatin{SA}
διατηρείται σταθερός στα ~21.8 σε όλες τις τιμές, χωρίς αξιοσημείωτη βελτίωση ή
επιδείνωση. Το συμπέρασμα είναι ότι ο ορίζοντας $H=5$ του \textlatin{RRHC} του δίνει
μικρό πλεονέκτημα όταν υπάρχει αρκετός χρόνος για εξερεύνηση.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\textwidth]{images/cartpole_episode_rewards.png}
    \caption{\textlatin{CartPole} -- Αθροιστική ανταμοιβή ανά επεισόδιο
    (\texttt{\textlatin{max\_timesteps}}=100, 1000 επεισόδια). Οι τρεις καμπύλες
    αλληλεπικαλύπτονται σε μεγάλο βαθμό, με υψηλή διακύμανση αλλά χωρίς
    συστηματική αλλαγή στη συμπεριφορά κατά τη διάρκεια των 1000 επεισοδίων.}
    \label{fig:cartpole_eps}
\end{figure}

Στο Σχήμα~\ref{fig:cartpole_eps} οι τρεις αλγόριθμοι παρουσιάζουν παρόμοια και
εναλλασσόμενη διακύμανση, με ανταμοιβές που κυμαίνονται από $\approx 10$ έως $\approx 88$
ανά επεισόδιο. Οι καμπύλες αλληλεπικαλύπτονται έντονα και δεν υπάρχει κάποιος
αλγόριθμος που να ξεχωρίζει ξεκάθαρα. Σημαντικό είναι ότι δεν παρατηρείται καμία τάση
υποβάθμισης ούτε βελτίωσης κατά τη διάρκεια των 1000 επεισοδίων: οι συνεχείς αλλαγές
παραμέτρων επηρεάζουν την ατομική δυσκολία κάθε επεισοδίου αλλά δεν μεταβάλλουν
συστηματικά την ικανότητα των αλγορίθμων.

\subsection{\textlatin{MountainCar}}

\begin{figure}[H]
    \centering
    \includegraphics[width=0.75\textwidth]{images/mountaincar_mean_rewards.png}
    \caption{\textlatin{MountainCar} -- Μέση αθροιστική ανταμοιβή ανά
    \texttt{\textlatin{max\_timesteps}} (100 επεισόδια). Και οι τρεις αλγόριθμοι
    ακολουθούν πρακτικά την ίδια γραμμή $y = -\texttt{\textlatin{max\_timesteps}}$,
    δείχνοντας ότι κανένας πράκτορας δεν καταφέρνει να φτάσει στον στόχο.}
    \label{fig:mcar_mean}
\end{figure}

Οι τρεις καμπύλες του Σχήματος~\ref{fig:mcar_mean} είναι ουσιαστικά αδιαχώριστες: και
οι τρεις αλγόριθμοι ακολουθούν γραμμικά την καμπύλη $y = -\texttt{\textlatin{max\_timesteps}}$,
δηλαδή αθροίζουν $-1$ ανά βήμα χωρίς ποτέ να επιτύχουν τον στόχο. Η μη-στασιμότητα
(αύξηση βαρύτητας και δύναμης) δεν αλλάζει αυτή την εικόνα: το πρόβλημα αντιμετωπίζεται
εξίσου ανεπιτυχώς σε όλες τις ρυθμίσεις.

\begin{figure}[H]
    \centering
    \includegraphics[width=0.95\textwidth]{images/mountaincar_episode_rewards.png}
    \caption{\textlatin{MountainCar} -- Αθροιστική ανταμοιβή ανά επεισόδιο
    (\texttt{\textlatin{max\_timesteps}}=100, 1000 επεισόδια). Και οι τρεις
    αλγόριθμοι παράγουν ακριβώς $-100$ σε κάθε επεισόδιο, χωρίς καμία εξαίρεση.}
    \label{fig:mcar_eps}
\end{figure}

Το Σχήμα~\ref{fig:mcar_eps} είναι ίσως το πιο χαρακτηριστικό αποτέλεσμα της εργασίας.
Ο άξονας $y$ έχει εύρος μόλις $[-105, -96]$ και και οι τρεις καμπύλες εμφανίζονται
ως μία και μοναδική οριζόντια γραμμή στο $-100$. Σε κανένα από τα 1000 επεισόδια
κανένας αλγόριθμος δεν έχει επιτύχει διαφορετικό αποτέλεσμα από το $-100$: κάθε
επεισόδιο τελειώνει εξαντλώντας όλα τα διαθέσιμα βήματα χωρίς το αυτοκίνητο να
αγγίξει ποτέ τον στόχο. Αυτό δείχνει πόσο αδύναμη είναι η \textlatin{one-step
lookahead} στρατηγική για ένα πρόβλημα που απαιτεί ανάπτυξη ορμής μέσα από πολλά
διαδοχικά βήματα.

\section{Συμπεράσματα}
% ============================================================

Στο \textlatin{CartPole}, και οι τρεις αλγόριθμοι αντεπεξήλθαν ικανοποιητικά,
επιβιώνοντας κατά μέσο όρο γύρω στα 21--24 βήματα ανά επεισόδιο. Ο \textlatin{HC}
αποδείχθηκε ανταγωνιστικός παρά την απλότητά του, αφού η εξισορρόπηση ράβδου είναι
εκ φύσεως αντιδραστική εργασία και η άπληστη επιλογή ενός βήματος αρκεί. Ο \textlatin{RRHC}
πέτυχε την καλύτερη μέση βαθμολογία στα μεγαλύτερα \texttt{\textlatin{max\_timesteps}}
($\approx 23.3$ στα 1000 βήματα), καθώς ο ορίζοντας $H=5$ επιτρέπει μια πιο
ολοκληρωμένη αξιολόγηση κάθε κίνησης. Ο \textlatin{SA} παρέμεινε σταθερός αλλά δεν
κατόρθωσε να ξεπεράσει τους άλλους δύο: η στοχαστική αποδοχή χειρότερων κινήσεων
δεν προσθέτει αξία σε ένα περιβάλλον όπου τα τοπικά βέλτιστα δεν είναι το κεντρικό
πρόβλημα. Αξιοσημείωτο είναι επίσης ότι η απόδοση όλων των αλγορίθμων δεν υποβαθμίζεται
κατά τα 1000 επεισόδια, πράγμα που δείχνει ότι το άμεσο σήμα ανταμοιβής του
\textlatin{CartPole} είναι αρκετά πλούσιο ώστε να στηρίζει σωστές αποφάσεις
ακόμα και όταν οι παράμετροι του περιβάλλοντος έχουν αλλάξει.

Στο \textlatin{MountainCar} το αποτέλεσμα είναι σαφές: και οι τρεις αλγόριθμοι
αποτυγχάνουν πλήρως. Η ανταμοιβή είναι ακριβώς $-100$ σε κάθε ένα από τα 1000
επεισόδια, χωρίς καμία εξαίρεση. Το πρόβλημα δεν είναι οι αλγόριθμοι -- είναι η
θεμελιώδης αδυναμία της \textlatin{one-step lookahead} στρατηγικής για μια εργασία
που απαιτεί ανάπτυξη ορμής μέσα από συντονισμένες, πολλαπλές κινήσεις. Το άμεσο
σήμα ανταμοιβής ($-1$ σε κάθε βήμα ανεξάρτητα από τη θέση) δεν δίνει καμία
πληροφορία που να βοηθήσει έναν \textlatin{greedy} πράκτορα να διαφοροποιήσει καλές
από κακές κινήσεις. Για να λυθεί το \textlatin{MountainCar} με τοπική αναζήτηση θα
χρειαζόταν είτε πολύ μεγαλύτερος ορίζοντας στον \textlatin{RRHC} (πολλαπλασιασμός
του $H$) είτε διαφορετική συνάρτηση ανταμοιβής που να ανταμείβει ανάλογα με την
απόσταση από τον στόχο.
